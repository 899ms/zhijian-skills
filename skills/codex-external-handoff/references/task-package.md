# Codex 外援任务包

任务包是外部 Agent（WorkBuddy、Claude Code 等）与 Codex 之间的最小契约。它不是整段聊天转储，也不自动携带外部环境的隐含上下文。

## 必需字段

```markdown
# 任务

## 目标
用一句话说明 Codex 要解决什么。

## 当前上下文
- 项目根：绝对路径
- 当前模块 / 任务阶段：如适用
- 已确认事实：只放改变判断的内容

## 输入与读取范围
- 允许读取的文件或目录
- 版本、日期和来源限制

## 禁止事项
- 默认不改文件、不改状态、不发布、不发送
- 不把未经验证的旧记录直接当确凿证据

## 任务
列出需要完成的分析、检索、审校或工程动作。

## 验收
- 结论可直接回答目标
- 每项关键判断有来源路径或验证
- 明确冲突、缺口和风险
- 给出建议状态增量，不直接写回权威状态
```

## 权限路由

- `read-only`：研究、跨项目取材、事实核验、结构审查、独立审校。默认使用。
- `workspace-write`：当前任务明确要求 Codex 落地工程修改，并已列出可写路径、验证方式。未满足任一条件时保持只读。

任务需要读取跨目录资料时，Thread 仍从目标项目根启动；任务包列出允许搜索的最窄目录、文件类型和排除项。不得把用户主目录、云盘根或其他宽泛目录作为递归搜索根。

## 结果合同

脚本要求 Codex 最终返回：

- `status`：`completed`、`blocked` 或 `needs_input`；
- `conclusion`：可供主线程判断的结论；
- `evidence[]`：来源与发现；
- `risks[]`：仍未关闭的风险；
- `artifacts[]`：真实存在的产物路径；
- `recommended_actions[]`：建议下一步；
- `suggested_state_delta`：建议写回内容，没有则留空字符串。

外部 Agent 必须先核验来源与产物，再决定是否采纳。
