## 使用规则

- 每章至少引用一个案例、反例或场景。
- 假设案例必须标明为 scenario。
- 用户真实案例必须标明公开程度。
- A 级案例：公开、可核验、有具体处境、动作、结果。
- B 级案例：公开但信息不完整，只作为辅助。
- C 级材料：需求、评论、场景抽象，只能写成“读者场景”“常见困惑”“反对意见”，不能标题写成案例。
- D 级材料：自有经验或匿名案例，必须标明边界。
- 行为层材料可以进入本表，但标题不能伪装成完整案例；优先写成“公开行为信号”。
- 交易层材料可以进入本表，但只能说明市场承诺和购买异议，不能证明交付质量。
- Nowledge/Obsidian 只在特别贴合时进入本表，默认标为 L6-owned 和 owned experience / scenario。
- 来自小红书评论的案例要匿名化处理，优先提炼成读者场景，不直接暴露个人信息。
- 来自公众号或网页的案例要记录原文来源，避免把二手转述写成事实。
